# HU-01 — Fortalecer la validación del token de autenticación

## Origen
- **Componente:** api
- **ID:** H-API-02 — Token Base64 con secreto embebido (Pendiente).
- **Evidencia:** `api/app/main.py:14`; `api/app/main.py:19-22`.

## Contexto
El hallazgo indica que el token no está firmado y que el secreto está en el código. En consecuencia, quien lo lea puede fabricar tokens con usuario, rol y expiración futura, y el servicio los aceptará.

## Ajustes necesarios
- Incorporar firma criptográfica al token y verificarla antes de aceptar sus datos.
- Retirar el secreto del código fuente y obtenerlo de configuración externa.
- Rechazar tokens sin firma, con firma inválida o con contenido alterado.

## Criterios de aceptación
- Una prueba verifica que un token correctamente firmado con una clave ficticia configurada sea aceptado.
- Una prueba verifica que un token cuyo contenido se alteró después de firmarlo sea rechazado.
- Una prueba verifica que se rechacen un token sin firma y uno firmado con una clave ficticia distinta a la configurada.
- Una prueba de configuración verifica que la clave de firma se obtenga de configuración externa y no esté embebida en el código fuente.

## Evidencia esperada
- Resultados de las pruebas de aceptación con claves ficticias aisladas.
- Revisión del código que confirme que no se incorporaron secretos reales ni se registran valores de tokens o claves.
